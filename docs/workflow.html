Railway Braking Monitoring Dashboard

FastAPI + React · Data Processing thesis project

How a braking cycle gets from a raw .bin file to a scored event on screen — traced through the backend pipeline and the frontend pages that read from it, in both the batch (ingest job) and live (watcher) paths.

01

System Architecture

Frontend ⇄ Backend ⇄ Pipeline

The React SPA never talks to the pipeline or the data files directly — everything crosses through FastAPI's four routers, which delegate to a thin services layer.

02

Backend — Batch Ingest Job

Jobs page → pipeline.py

Submitting a date range on the Jobs page kicks off a two-stage background job. A single bad day is caught and skipped rather than failing the whole range.

03

Backend — Live Watcher

Live page → live_watch.py

Starting a watcher spins up an indefinite per-kit thread — not a one-shot job — that polls a folder, detects cycles incrementally, and scores each one the moment it closes.
